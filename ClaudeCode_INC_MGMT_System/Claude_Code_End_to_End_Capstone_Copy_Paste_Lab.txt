CLAUDE CODE CAPSTONE LAB
FROM ONE-PARAGRAPH CLIENT REQUIREMENT TO WORKING APPLICATION
Student / Instructor Copy-Paste Notepad
============================================================

GOAL
----
Create a working IT Support Ticket Management System using Claude Code's
orchestrator and six specialized subagents. Complete requirements analysis,
architecture, implementation, testing, security review, local launch and
handover. No cloud deployment.

PREREQUISITES
-------------
- VS Code
- Claude Code installed and authenticated
- Python 3.10+ installed
- Working Claude Code model access
- Internet access for Python dependency installation

IMPORTANT INSTRUCTIONS
----------------------
1. Create an EMPTY folder named IT-Support-Agentic-Project and open it in VS Code.
2. Open VS Code Terminal, run `claude`, and sign in if necessary.
3. Prompts labeled "PASTE INTO CLAUDE CODE" must go into the Claude Code
   interactive prompt, not the normal shell.
4. Paste one numbered prompt at a time. Check outputs before moving on.
5. Approve file changes and terminal commands after reviewing them.
6. If Claude Code is interrupted, resume in the same project folder.
7. Agent names, files, and commands must be VERIFIED; do not accept an agent's
   unverified claim that a test passed or an app started.
8. This is a LOCAL DEMO app. A role selector is NOT real login/security.

STEP 2 — CREATE THE ENGINEERING AGENT TEAM
============================================================

PASTE INTO CLAUDE CODE — PROMPT 1:

We are starting a new enterprise software engineering project in this empty folder.

Act as the Lead AI Engineering Orchestrator.

Your first task is ONLY to initialize the AI engineering team and project instructions. Do not build the application yet.

Create the following six specialized Claude Code subagents as Markdown files inside .claude/agents/:

1. requirements-analyst
   - Analyze client requirements.
   - Identify ambiguities, assumptions and missing details.
   - Prepare user stories, functional requirements and acceptance criteria.
   - Do not implement application code.

2. solution-architect
   - Design application architecture, modules, data models and database schema.
   - Define interfaces between UI, service and database layers.
   - Prepare a practical technical implementation plan.
   - Do not implement application code.

3. backend-developer
   - Implement Python business logic, persistence and validation.
   - Use SQLite with Python's built-in sqlite3 module.
   - Own backend service and database files.
   - Follow approved architecture and interface contracts.

4. frontend-developer
   - Develop the Streamlit user interface.
   - Create forms, tables, filters and dashboard visualizations.
   - Use backend service interfaces instead of embedding SQL in UI code.
   - Own UI files.

5. qa-engineer
   - Create and execute pytest tests.
   - Verify acceptance criteria and edge cases.
   - Report defects and test evidence.
   - Do not silently change production code.

6. security-reviewer
   - Review input validation, SQL injection risks, secrets, permissions and insecure workflows.
   - Run appropriate checks when tools are available.
   - Report actionable findings with severity.
   - Do not claim a vulnerability is fixed unless retested.

Each custom agent must have valid Claude Code YAML frontmatter, including name, description and appropriate tools supported by this installation.

Use lower-risk read-only tools for analysis/review agents where practical. Give implementation agents the necessary file editing and command execution capabilities.

Also create a CLAUDE.md file containing:
- Project purpose
- The Lead Orchestrator's responsibilities
- Available subagents and their responsibilities
- Mandatory delegation rules
- Planning-before-coding requirement
- Agent file ownership rules
- Testing and quality requirements
- Human approval checkpoints
- Requirement traceability rules
- No cloud deployment without explicit approval

The orchestrator must delegate meaningful work to the configured subagents rather than impersonating their roles.

Create a docs/ directory for project documentation.

After creating the configuration:
1. Show the project directory structure.
2. List the six agents and their responsibilities.
3. Explain how agent delegation will happen.
4. Stop and wait for my next instruction.

Do not create application code in this step.


CHECKPOINT: You should see CLAUDE.md and six files in .claude/agents/.

"Our company needs a simple IT Support Ticket Management System. Employees should be able to raise support tickets with details of their issues, assign priorities, and track progress. We want the system to be easy to use, store information permanently, and work from a web browser."

5. Define testable acceptance criteria.
6. Identify ambiguities and risks.

9. Save the outputs in docs/.

Important:

STEP 5 — APPROVE MVP SCOPE AND DESIGN THE ARCHITECTURE
============================================================

PASTE INTO CLAUDE CODE — PROMPT 4:

I approve the following scope for the local classroom MVP:

- Python 3.10+.
- Streamlit user interface.
- SQLite using Python's built-in sqlite3.
- Pytest for tests and Ruff for linting.
- Employee, Support Engineer and Manager views.
- Employee can create tickets and view ticket status.
- Engineer can inspect tickets, change priority/status and add resolution notes.
- Manager dashboard displays total, open, in-progress, resolved and closed counts, plus priority and category breakdowns.
- Ticket fields: ID, title, description, category, priority, status, creator, created_at, updated_at and resolution_note.
- Status values: Open, In Progress, Resolved, Closed.
- Priority values: Low, Medium, High, Critical.
- Persist tickets in a local SQLite database.
- For simplicity use a clearly labeled DEMO role selector, not real authentication. This is not secure authorization and must be disclosed in documentation.
- No cloud services, external APIs or deployment.

Delegate architecture design to the solution-architect subagent.

Ask it to produce:
1. System architecture.
2. Application module responsibilities.
3. SQLite schema.
4. Service-layer contracts.
5. UI design and navigation.
6. Validation requirements.
7. Testing strategy.
8. Implementation work breakdown.
9. Explicit file ownership for backend and frontend agents.
10. Integration dependencies and parallelizable tasks.

Save the design documents under docs/.

Ensure the architecture is intentionally simple enough for a classroom demonstration.

Do not implement application code yet.

Review the architect's output, summarize the implementation plan, then stop.


CHECKPOINT: Review architecture, schema, and implementation plan.

3. Have the QA agent independently rerun the affected tests.

5. Escalate unresolved failures rather than hiding them.

7. Save a report in reports/test-report.md.

- Defects discovered
- Fixes applied

Execute the tests for real. Do not simulate test results.
