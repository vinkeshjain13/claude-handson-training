======================================================================
HOW TO USE THIS HANDOUT
======================================================================
This is a fully guided lab. Begin with an EMPTY project folder. Follow
steps in order; do not paste shell commands into Claude Code or Claude
prompts into the shell. Each step includes WHY, DO, CHECK and FIX.

Environment:
- VS Code, terminal, Python 3.11+ and preconfigured Claude Code CLI.
- Git, a GitHub account, and Streamlit Community Cloud account for deploy.
- No OpenRouter, Anthropic API key, or application runtime API required.
- The delivered app uses deterministic local Python business rules. Claude
  Code is used to DEVELOP the app; the app itself does not call Claude.
- Use only SYNTHETIC sample data. Never publish real customer data.

Important: Claude Code already handles supported prompt-prefix caching
internally. We do NOT write cache_control code into this Streamlit app.
CLAUDE.md is reusable project instruction context, NOT a persistent LLM
response cache. Documentation and scoped file reads may reduce repeated
exploration, but are NOT equivalent to provider-side prompt caching.
Your account may not expose cache-hit counters or dollar cost.
Do not claim caching savings without available telemetry.

Time plan: 10m brief; 10m setup; 15m subagents; 25m implementation;
15m testing; 20m context/cost experiments; 15m deployment; 5m review.

COPY INTO CLAUDE CODE:

- Add .gitignore for .venv/, __pycache__/, .pytest_cache/, .env,

PART C — COMPARE RE-EXPLORATION VS TARGETED REUSE (8 MIN)
Use two small, equivalent READ-ONLY reviews. Because tool calls and

PROMPT A (broad):
Review the entire repository and identify one opportunity to simplify
classify_ticket(). Do not edit files. Report how many files you inspected
and tool operations you used when available.

PROMPT B (targeted):
Consult CLAUDE.md and docs/architecture.md. Inspect only
src/ticket_logic.py and related tests as necessary. Identify one
opportunity to simplify classify_ticket(). Do not edit files. Report
how many files/tool operations you used when available.

Write down:
  Broad review files inspected: __________
  Targeted review files inspected: ________
  Broad tool calls (if shown): ___________
  Targeted tool calls (if shown): ________
  /cost values (if exposed): ____________
  Cache write/read tokens (only if exposed): ____________

IMPORTANT INTERPRETATION:
- Comparing consecutive prompts is NOT a controlled cost benchmark.
- Targeted reads can reduce unnecessary tool output/context, but may
  not always cost less, and cached input might change the economics.
- /compact summarizes long chat context; /clear resets chat history.
  Neither is a general-purpose reusable answer cache. Do NOT run /clear
  mid-experiment; it destroys comparability and conversation continuity.
- Use /clear when switching to unrelated work, /compact to continue
  a lengthy active task; both may change caching behavior.
- If /cost is unavailable, assess file reads and tool calls; do not
  manufacture 'saved dollars'.
